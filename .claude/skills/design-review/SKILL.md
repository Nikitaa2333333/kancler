# Дизайн-ревью «Канцлера»

Пользователь много раз находил одно и то же сам, со скриншотов с телефона:
тире в списках, линии над первым пунктом, плашки в плашках, синий текст,
дыры между блоками. Этот скилл нужен, чтобы такие вещи ловились **до** того,
как пользователь их увидит.

| Файл | Что там |
|---|---|
| `references/rules.md` | **свод правил** — что разрешено и что запрещено, с номерами правок из журнала |
| `scripts/check-render.mjs` | проверка отрисованных страниц (390 и 1280 px), коды находок — в шапке файла |
| `src/styles/tokens.css` | палитра («ПАЛИТРА — СВОД»), кегли, отступы — **читать, а не помнить** |
| `docs/правки-2026-10-28.md` | журнал правок пользователя: откуда взялось каждое правило |

## Порядок работы

1. **До правки.** Прочитать `rules.md`. Найти готовый компонент (раздел
   «Готовые компоненты» в своде) — не писать новый приём, если есть свой.
2. **Правка.** Только токены. Новый приём — сначала предложить пользователю,
   после «да» записать в `rules.md`.
3. **После правки** — при работающем `npm run dev` (порт 4340):
   ```
   node .claude/skills/design-review/scripts/check-render.mjs
   ```
   Должно быть «Находок нет». Можно перечислить страницы:
   `… /buhgalterskiy-uchet/ /kontakty/`. Новую страницу — дописать в `PAGES`
   в скрипте.
4. **Глазами** — полностраничные скриншоты 1280 и 390 (Playwright), смотреть
   то, что скрипт не умеет: ритм, одинаковость карточек в ряду, пустоты внутри
   карточек, смысл группировки.
5. `npx astro check` и `npm run build` — без ошибок.
6. Записать правку в журнал, PR → слияние → дождаться выкладки → ссылка.

## Исключения в скрипте

- `[data-design-ok]` на элементе — скрипт его пропускает. Ставить только
  с комментарием, почему правило здесь не действует, и только после
  согласия пользователя.
- Не проверяются: шапка, подвал, графики кейсов (`charts`), чертежи
  `Shapes`/`AudienceUI`, картинки кейсов.

## Ловушки

1. **Линия «между» ≠ линия «сверху».** Всегда `li + li { border-top }`, никогда
   `li { border-top }` — иначе линия над первым пунктом (пользователь ловил
   четыре раза).
2. **Плашка в плашке появляется сама**, когда карточки с `--card-bg` попадают
   в цветную секцию. Карточки-плашки — только в белой секции (`white` у `Sec`,
   `.sec--white`); в цветной секции — содержимое без подложек.
3. **Анимация появления** (`data-reveal`, серые пункты «Типичных ситуаций»)
   — в замерах скрипт снимает её стилем; на скриншоте Playwright картинки
   с `data-reveal` могут выйти пустыми — это не баг страницы.
4. **Порядок на телефоне ≠ порядок в коде** в таблицах цен: на телефоне
   `order` ставит цену сразу под название.
5. **Высота карточек для компьютера** (`min-height`) на телефоне даёт пустоты
   — сбрасывать в `@media (max-width: 760px)`.
