# Канцлер — сайт бухгалтерского и управленческого учёта для строительных компаний

Консалтинг «Канцлер» (основатель Диков Вадим Александрович): бухгалтерия и управленческий
учёт для строительных компаний МСБ, Москва и МО, работаем дистанционно, с 2012 года.
Цель сайта — заявки из Яндекс.Директа и поиска. Общие правила работы, типографика, токены
отступов, мера строки, запрет капса и жирности в тексте — в глобальном `~/.claude/CLAUDE.md`,
здесь не дублируются.

Репозиторий: `D:\kancler` → GitHub **Nikitaa2333333/kancler** (публичный: на бесплатном
тарифе GitHub Pages работает только из публичного репозитория; секретов в коде нет, `.env`
в gitignore). Тестовая выкладка: https://nikitaa2333333.github.io/kancler/ — автоматически
из `main` (`.github/workflows/pages.yml`, PUBLIC_BASE=/kancler). Боевой хостинг — SprintHost
позже (скилл `sprinthost-deploy`); сайт там с корня, PUBLIC_BASE не задаём. Все внутренние
ссылки и пути к файлам — только через `u()` из `src/lib/url.ts`. Фаза:
**главная собрана на Astro по ТЗ и токенам Avenir (22.10.2026), идёт доводка глазами.**

Запуск: `npm run dev` → http://127.0.0.1:4340/ (порт закреплён). Сборка `npm run build`,
проверка типов `npx astro check`. Стек: Astro 5, чистый CSS на токенах (без Tailwind),
шрифты Lora + Inter Tight через `@fontsource-variable`.

Карта кода: токены — `src/styles/tokens.css`, база — `src/styles/global.css`; тексты —
`src/data/home.ts` (дословно из ТЗ), данные компании — `src/data/company.ts` (пустое поле =
не выводится); секции — `src/components/sections/*`; страница — `src/pages/index.astro`.
Типографика (nbsp) — `src/lib/typo.ts`, прогоняем все тексты. Отступы — `SPACING.md`.
Сайт закрыт от индексации (`PUBLIC_INDEXING`, `robots.txt`) до выбора домена.

## Что решено

- Выбран **вариант 1** (базовая структура). Блоки главной по порядку: шапка · первый экран ·
  для кого мы работаем · проблемы клиента · услуги · преимущества · кейсы · как мы работаем ·
  о компании · что влияет на стоимость · форма заявки · подвал.
- На главной **нет цен**: цены будут на страницах услуг (клиент пришлёт файлы). Есть блок
  «Что влияет на стоимость» — у бухгалтерской колонки текст готов, у управленческой клиент
  пока написала «ДУМАЕМ».
- Адрес офиса не показываем (работаем дистанционно). Часы работы: с 8:00 до 20:00.
- Отзывы пока не показываем.
- Заявки идут на почту **kanc_konsalt@mail.ru** (плюс Telegram и цель Метрики — по нашему
  документу «Понимание задачи»).
- Программы: 1С: Бухгалтерия, Диадок, СБИС/Тензор, Контур.Экстерн.
- Кейсов три, каждый клиент пришлёт отдельным файлом: Штрафстоянка; строительная компания
  «А»; группа компаний «упр учёт»/«анализ».
- Сайт многостраничный: главная, бухгалтерский учёт, управленческий учёт, кейсы (список +
  страница на каждый), контакты. Сначала делаем главную.
- **Годы:** пишем так, как в ответах клиента, — «с 2012 года». Формулировка «12 лет на рынке»
  из текста первого экрана снимается (решение пользователя 22.10.2026).
- **Преимущества:** в доке клиента цифры 1, 2, 6 — это номера плашек макета, которые она
  меняет. Плашка 1 → «Специализация на строительном учёте», 2 → «Профответственность
  застрахована», 6 → «Защита данных по объектам». Плашки 3, 4, 5 остаются как в макете
  («Понятные отчёты», «Личный бухгалтер», «На связи в мессенджерах»).
- **Фирменный стиль и логотип не делаем** (решение пользователя 22.10.2026). Вместо логотипа —
  текстовая вордмарка «Канцлер», набранная шрифтом сайта. Палитра, шрифты и графика —
  в рамках дизайна сайта, не как отдельная работа с логотипом и брендбуком.
- Управленческий учёт в блоке «Что влияет на стоимость»: клиент пишет «ДУМАЕМ» — ждём её
  текст, сами не заполняем.

**Первый экран (23.10.2026):** текст слева, видео справа отдельным блоком — фото под
текстом пользователь не хочет. Видео `public/video/hero.mp4`: ОДИН непрерывный кадр (без
склеек — требование пользователя), 5 с, без звука, играет один раз и стоит на последнем
кадре (стройка за окном). Сделано в image-styler: первый кадр — сцена `hero-window`
(пресет `kancler-flash`), анимация — пресет `kancler-video-seedance` (Seedance 2 Mini,
720p). Грабля polza.ai: `duration` для Seedance — строка из цифр (`"5"`), не `"5s"` и не 5.
Постер — `public/images/hero-window.jpg`. Тёмное «кофейное» фото стола сверху снято.

- Преимущества и шаги: пункты одного вида (только заголовки, без описаний макета), сетка с
  линиями сверху, без плашки-в-плашке.
- «О компании»: фото + заголовок + таблица фактов (основатель, на рынке, регион, часы) — без дыр.
- «Что влияет на стоимость» — таблица «Фактор / Почему влияет»; текст клиента разделён
  ровно по скобке, слова не менялись.
- Заявка: голубая плашка без штриховки. Подвал: простой, две линии, копирайт слева,
  политика справа.
- Выдуманные цифры макета кейсов на сайт не идут.
- Нумерацию блоков в доке клиента не чиним (порядок как в ТЗ).

## Открытые вопросы к клиенту

1. Телефон и мессенджеры (TG, WhatsApp, Макс?) для шапки, формы и подвала — пользователь
   спросит у клиента.
2. Реквизиты для подвала (название юрлица, ИНН, ОГРН) и политика конфиденциальности.
3. Блок «О компании»: фото основателя (Диков Вадим Александрович), цитата, опыт,
   квалификация, сертификаты; фото команды и офиса — есть ли.
4. Профответственность застрахована: сумму и полис называть на сайте или нет.
5. «Для кого»: в макете «Инженерные компании», клиент дописала «Инжиниринговые компании» —
   одно и то же или две карточки.
6. «Проблемы клиента»: заголовок «Знакомо?» оставляем? Клиентский список из 6 пунктов
   заменяет 5 карточек макета — подтвердить.
7. «Как мы работаем»: шаги 1, 3, 5 не правились — оставляем текст макета. Сроки шагов не
   названы («8 пункт» в ответе — это отсылка на блок 8 структуры).
8. Кейсы: три файла от клиента. Можно ли называть клиентов, показывать обезличенные
   отчёты — нет ответа.
9. Ответы без текста: типичный клиент, частые проблемы, почему выбирают нас, гарантии и
   ответственность по договору.
10. Файлы по услугам (что входит в бухгалтерский и в управленческий учёт) — «в процессе работы».
11. Домен, хостинг, регистратор — не выбраны. Нужно решить и назвать клиенту.

## Дизайн: направление

Референс — шаблон **Avenir** (`docs/reference/avenir-hero.jpg`). Пользователь: это
основа, к которой надо прийти, но не копия; сначала смотрим похожие по стилистике сайты и
делаем сильнее. Что считываем в референсе:

- крупное фото-hero в скруглённой рамке с белым полем вокруг, заголовок прямо на фото;
- заголовки антиквой (serif, плотный тёмный сине-зелёный цвет на светлом тёплом фоне);
- светлая тёплая бумага вместо белого, карточки светло-серые, без теней;
- линейные иллюстрации-круги (радиальные штрихи) как иконки услуг;
- в тексте-манифесте мелкие фото-вставки между словами; строка рейтинга со звездой;
- спокойная сдержанная типографика, мало цвета, много воздуха.

Что надо учесть для строительной бухгалтерии (не копировать слепо): вместо офисных людей
на фото — реальные образы стройки/планов/смет; фирменные цифры и отчёты как графика; цифры
оформлять заметно (это язык клиента). Дизайн собирается по токенам и правилам глобального
CLAUDE.md (контрастный текст, без капса и жирности внутри фраз, мера строки, `SPACING.md`).
